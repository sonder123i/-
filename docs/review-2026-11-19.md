## 三、三路评审结论摘要

### 安全（SHIP WITH FIXES）
- **更新链是本次最扎实的部分**：清单先验签后解析、P-256 密钥强度校验、域名白名单（仅 HTTPS/443、拒绝 userinfo/私有地址）、禁用重定向并逐跳校验、SHA-256 + ABI + 包名 + versionCode + 签名证书一致性、下载与安装前各验一次、拒绝降级。
- 剩余 P1：**发布签名私钥在 git 历史中**（见第四节）。它不影响应用内更新（清单另有 ECDSA 签名），但会让“同签名 APK 覆盖安装”成为可能。
- 其余 P3：更新弹窗/版本查询的 IPC 开销（已修）、JitPack 依赖未固定、Shizuku 进程未 `destroy`、剪贴板未标敏感（旧 `MainActivity`，已不可达）。

### 代码质量（SHIP WITH FIXES）
- 未发现可构造的崩溃、数据丢失或代码执行路径。
- 主要问题集中在新增 GLES/玻璃层与前台服务每 tick 的开销；P1（玻璃不刷新）已修。
- 仍建议后续处理：`NavShadowView` 在硬件层使用 `BlurMaskFilter` 会导致阴影变硬边；悬浮胶囊每帧重建渐变（60fps × 1~2 小时）；`GlassRenderGate.unregister()` 无调用方；`StatusOrbView` 切换状态后呼吸节奏不更新；`SpecularButton` 一次抑制后不再恢复。

### 架构（READY WITH DOCUMENTED DEBT）
- `run/` 分层整体健康，`EngineEnv` + JVM 测试是可维护性的核心资产。
- 上次评审的三步走：第一步（安全/生命周期）已完成；第二步**未开始**（`FreeRoamController` 仍在 `ui`、无 `SessionCoordinator`）；第三步部分（`RouteEditorActivity` 已涨到 2372 行，`RunSessionService` 576 行）。
- 约 4k 行旧代码（`MainActivity` / `SettingsActivity` / `HistoryActivity` / `JoyStick`）已不可达，但仍参与编译并被 `ServiceGo` 引用常量。建议先抽常量、标 `@Deprecated`，下个版本删除。
- 缺少 `CONTRIBUTING.md`、`CHANGELOG.md`、版本目录；Room `exportSchema = false`。

## 四、需要你拍板（发布前）

### 1. 发布签名文件的历史遗留（P1）
`keystore/GoGoGo.jks` 曾被仓库跟踪，本次只是停止跟踪，**历史提交里仍可恢复**；同一签名在公开的上游仓库中也已经存在。因此它应被视为“公开的签名身份”，而不是普通密钥。三个选项：

| 方案 | 代价 | 适用 |
|---|---|---|
| A. 接受它是“公开身份”，不轮换 | 旧包可被同签名覆盖安装；需在安全说明中写清 | 已是既有发布签名、不能断更 |
| B. 用 APK Signature Scheme v3 lineage 轮换（仅 API 28+ 可平滑升级，minSdk 27 设备需重装） | 需要新 keystore + lineage 文件，并做一次真机验证 | 推荐，若你愿意承担一次过渡发版 |
| C. 重写 git 历史（filter-repo）再公开 | 上游已公开同一签名，收益有限；只用于新仓库首次推送 | 新仓库且未推送过任何历史 |

不论选哪个，建议给更新清单增加 `signerSha256` 字段并在 `verifyApk()` 里比对，避免更新链依赖“当前安装包签名”这一隐含信任。

### 2. 更新通道尚未真正上线
`docs/update/stable.json` 不存在，首次自动检查会 404。另外 `docs/update/README.md` 写的是 `main` 分支，CI 只在 `master` 上触发。发布前要么先发一版清单，要么把 `UPDATE_ENABLED` 关掉。

### 3. 百度地图 SDK 的再分发条款
`app/libs` 里的 jar/so 是专有组件，已补 `THIRD_PARTY_NOTICES.md` 说明其不在 GPL 范围内。正式对外前请确认百度条款允许在开源仓库中再分发这些二进制；若不允许，需要改为“构建时自行下载”。

## 五、建议的发布顺序

1. 确认第 4.1 的签名方案并落地；第 4.2 决定更新通道是否随首发开启。
2. `git add -A` 前再跑一次 `git status --porcelain --ignored`，确认 `.tmp_mumu/`、`.zcode/`、`go_run.db*` 都不在列表里。
3. 把当前工作区拆成可评审的提交（建议：签名/CI、安全修复、UI 修复、文档与许可）。
4. 打 tag 前用干净 clone 跑一遍 `assembleRelease` + `testDebugUnitTest`（本次已验证）。
5. 发布说明里写明：GPLv3、百度 SDK 除外、更新签名公钥、已知限制（targetSdk 32、arm64-only）。
