## 三、已修复清单（18 处）

### P0 — 双前台通知

| # | 位置 | 问题 → 修法 |
|---|------|------------|
| 1 | `RunSessionService.ensureServiceGo()` | 巡航时 `startForegroundService` 把 ServiceGo 拉成前台（IMPORTANCE_DEFAULT 会发声），与巡航通知并存 → 改为**仅绑定**，前台由会话服务独占 |

### P1 — 生命周期 / 时序

| # | 位置 | 问题 → 修法 |
|---|------|------------|
| 2 | `RunSessionService` ACTION_START | `RoamService.stop()` 先于绑定 → `RoamService.onDestroy → release()` 可能杀掉刚被巡航拉起的 ServiceGo，卡"准备中"。修法：**先绑先得**——先 `ensureServiceGo()` 再停漫游，绑定在先即可在 stopService 下存活 |
| 3 | `RunSessionService.onDestroy` | 只解绑不 stopService，ServiceGo 若处于 started 状态会带通知+注入循环永久残留 → 解绑后 `stopService` 兜底 |
| 4 | `ServiceGo.onStartCommand` | 无坐标 extras 的启动会把位置重置为济南默认值 (36.667,117.027) 并以 10Hz 注入，位置先闪跳济南 → 只在携带显式坐标时重置；并移除 onCreate 的注入循环自启动（等待显式坐标或引擎接管，避免默认坐标空注） |
| 5 | `ServiceGo.setEngineDriven(false)` | `mJoyStick.show()` 会复活已停用的旧摇杆浮窗（与新悬浮胶囊同屏）→ 删除，false 分支只恢复注入循环 |
| 6 | `RunSessionService.maybeStartEngine` / `onRunFinished` | Shizuku `waitFor()` 是进程阻塞调用，跑在主线程协程里，开跑/收尾瞬间可卡数百 ms~秒级，Shizuku 挂起则 ANR → 两处均移入 `withContext(Dispatchers.IO)` |
| 7 | `RouteEditorActivity.setupSearch` / `FreeRoamFragment.setupSearch` | 百度 SuggestionSearch 回调到达时页面可能已销毁，`AlertDialog.show()` 抛 BadTokenException → 回调入口加 `isFinishing/isDestroyed` / `isAdded` 判活 |

### P1 — 攻击面

| # | 位置 | 问题 → 修法 |
|---|------|------------|
| 8 | `AndroidManifest.xml` ×3 activity | RunHomeActivity / RunEngineDemoActivity / RouteEditorActivity `exported="true"`：可绕过欢迎页协议门槛（永久写 KEY_ONBOARDED）、借 `auto_route_id`/`auto_km` extras 静默自动发车、借 `linked_pkg` 让服务拉起任意已安装 app → main 收敛为 **exported=false**，adb 调试入口移入 `app/src/debug/AndroidManifest.xml`（仅 debug 变体放开） |

### P2 — 质量与纵深防御

| # | 位置 | 问题 → 修法 |
|---|------|------------|
| 9 | `FreeRoamController.release()` | 无条件 `stopService(ServiceGo)`，巡航进行中触发会误杀 → 加 `RunSessionHolder.sessionActive` 检查（启动竞态由 #2 的"先绑先得"兜底） |
| 10 | `FreeRoamController.onServiceDisconnected` | 只清 injector 不复位 `bindRequested`，断连后 `attach()` 永久 early-return，漫游静默失效 → 清理绑定标志并解绑，下次 attach 干净重绑 |

## 四、未修复，留给你拍板（按优先级）

1. **keystore/GoGoGo.jks 在 git 里 + storePassword 硬编码**（P2，上游遗留）。上游仓库本身就公开了这个 keystore，所以"拿到仓库就能签出同签名 APK"是上游现状的延续。若要收口：`git rm --cached keystore/GoGoGo.jks` + 密码迁入 local.properties——但会改变你的本地打包流程，需要你决定。
2. **targetSdk 32 → 34**（P2）。Manifest 已按 Android 14 规范声明好（本次还补了 ServiceGo 的 type），但升 targetSdk 是行为变更：location 型前台服务、POST_NOTIFICATIONS 请求流都需要真机回归。建议单独开一个分支做。
3. **RunCruiseEngine 跨线程字段竞态**（P2）：主线程调 pause/resume/insertDetour 与 Dispatchers.Default 的 tick 循环并发读写非 volatile 字段，目前靠 StateFlow 写入"事实上"保序，逻辑上脆弱。修法是状态收敛进单线程命令循环——属于重构，需要清醒时做。
4. **架构三步走**（来自架构评审，务实路线，不建议大重写）：
   - **第一步（已完成大部分）**：双通知清零、旧摇杆陷阱拆除、exported 收敛 ✅；剩余：每项改动在 Emulator API 34 上过一遍发车→锁屏→暂停→收尾。
   - **第二步（1-2 周）**：FreeRoamController 移入 `run/service`（消除 service→ui 反向依赖）；ServiceGo 通知点击改中立入口、常量挪出 MainActivity（消除旧→新编译依赖）；新建 `SessionCoordinator` 统一漫游/巡航互斥（现在散落在 4 个发车入口）；补 `isResumable`/`StepGuard`/`RouteShareCodec` 边界三个纯函数测试。
   - **第三步（持续）**：RouteEditorActivity（2145 行）按 `RouteSources` 先例逐块抽出；RunSessionService（530 行、7 种副作用）同法拆分；命名冻结——新资源一律 `dr_`，`pf_` 只减不增，上游遗留名随 MainActivity 下线一并回收。
5. **性能小项**（P3）：尾迹点每次追加全量复制 1200 点列表重画 Polyline（驱动时 5-10Hz），可改环形缓冲+增量 append；`testOptions.returnDefaultValues=true` 会掩盖未 mock 的 Android 调用，建议仅对确需的类用 Robolectric。
